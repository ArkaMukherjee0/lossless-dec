Nov 2018

Blockwise parallel

NeurIPS '18arXiv 1811.03115draft heads

Introduces Adds k output heads so one forward pass guesses the next k tokens; the next pass scores them with the base model and keeps the longest prefix that matches its own greedy choices, cutting the number of sequential steps.

Falls short The base model must be trained with the extra heads, and acceptance is an exact match to the greedy token, so it supports greedy decoding only and gives no distribution guarantee when sampling.

Speculative decoding

ICML '23 · SpS arXiv '23arXiv 2211.17192draft modelour path

Introduces A small draft model proposes k tokens and the target scores them all in one forward pass; a probabilistic accept/reject rule, with resampling from the residual on rejection, keeps the output exactly the target's distribution at any temperature.

Falls short Needs a second model with the same vocabulary, drafts one fixed-length chain one token at a time, and discards everything after the first rejection. At large batch verification turns compute-bound, so the speedup shrinks.

Apr 2023

LLMA

arXiv '23arXiv 2304.04487copy draftingour path

Introduces When the output is likely to repeat a reference text (retrieved documents, earlier turns), copies a span from that reference as the draft and checks all copied tokens in one target pass, keeping the matching prefix.

Falls short Speedup exists only when the output overlaps a reference; open-ended generation has nothing to copy. Checks are exact matches against greedy decoding, so sampling is not covered.

Answered by REST, Lookahead

May 2023

SpecInfer

ASPLOS '24arXiv 2305.09781token trees

Introduces Builds a token tree from one or more small drafters and verifies every branch in a single target pass with a tree attention mask, so a rejection on one branch can leave another accepted; multi-step speculative sampling keeps sampling exact.

Falls short The tree follows a fixed expansion setting, blind to budget, hardware and how predictable the context is. Verification also walks the tree token by token, rejecting some branches that a joint check would keep.

Answered by Sequoia, SpecExec, Traversal verif.

Aug 2023

Staged SD

ES-FoMo '23arXiv 2308.04623hierarchical drafting

Introduces Targets batch-1, on-device decoding: arranges draft candidates as a tree to raise the expected tokens per target pass, and speeds up the drafter itself with a second speculative stage that uses an even smaller model.

Falls short The same drafter produces every position, though tokens deep in the draft are rarely accepted, so much drafting cost buys tokens that get thrown away. Evaluated with a 762M GPT-2 target.

Answered by Cascade SD

Sep 2023

Draft & Verify

ACL '24arXiv 2309.08168self-speculation

Introduces Self-speculation: the target drafts by running with some intermediate layers skipped, then verifies with all layers. No extra model or training; the skip set is found by Bayesian optimization, and drafting stops early when confidence drops.

Falls short The skip set comes from a slow offline search and stays fixed per task, and an untrained layer-skipped model is a weak drafter, so acceptance is limited and speedups top out near 2x.

Answered by SWIFT, LayerSkip, Kangaroo, Cassandra

Oct 2023

DistillSpec

ICLR '24arXiv 2310.08461drafter training

Introduces Distils the drafter toward the target before deployment, training on sequences the drafter itself generates (on-policy) and picking the divergence to suit the task and decoding strategy, so drafts agree with the target more often.

Falls short Distillation happens once, offline, on a fixed dataset, so acceptance falls when live queries drift from it. Its token-level divergence also does not directly maximize how many consecutive draft tokens are accepted.

Answered by Online SD, EAL/WTV

Oct 2023

Online SD

ICML '24arXiv 2310.07177drafter training

Introduces Keeps updating the drafter during serving: positions where the draft disagreed with the target are buffered, and the drafter is periodically distilled on them using spare compute, so it adapts to the live query distribution.

Falls short Gains depend on the query stream being narrow or stable enough for a small drafter to learn, continual training needs spare serving capacity, and the small drafter's capacity gap to the target still caps acceptance.

Oct 2023

SpecTr

NeurIPS '23arXiv 2310.15141multi-draft

Introduces Samples k candidate drafts and picks among them with a selection rule derived from optimal transport, raising the chance that some draft token is accepted while keeping the output distribution exact.

Falls short The optimal selection is a linear program exponential in k, so SpecTr uses an approximate rule guaranteed only within a factor (1-1/e) of optimal; drafting k sequences also multiplies drafter cost.

Answered by Multi-draft opt.

Nov 2023

REST

NAACL '24arXiv 2311.08252retrieval draftingour path

Introduces Replaces the drafter with retrieval: matches the current suffix against a large text or code datastore through a suffix array, builds a tree from the continuations found, and verifies it in one target pass. No training needed.

Falls short The datastore is static and large, so it helps mainly in its own domain and misses repetition specific to an app's traffic; lookup needs an exact suffix match, which often fails and leaves no draft.

Answered by SuffixDecoding, SAM Decoding, LogitSpec

Nov 2023

Prompt lookup

code '23n-gram lookup

Introduces Drafts by string matching: finds the last few generated tokens elsewhere in the prompt and proposes the tokens that followed them there. No model needed, and effective when outputs quote the input, as in summarization, document QA and code editing.

Falls short It searches only the current prompt, so it misses reuse across requests and past outputs, and it needs an exact n-gram match, which open-ended text rarely provides.

Answered by SuffixDecoding, SAM Decoding, LogitSpec

Dec 2023

Cascade SD

NeurIPS '24arXiv 2312.11462hierarchical drafting

Introduces Two cascades of drafters. Vertically, each drafter is itself sped up by a smaller one, down to a cheap statistical model. Horizontally, early draft positions, the most likely to be accepted, get larger drafters and later positions smaller ones.

Falls short Needs a ladder of drafters of different sizes hosted together, and how positions are split across levels is a hyperparameter tuned per model setup, so deployment cost grows with every level.

Jan 2024

Medusa

ICML '24arXiv 2401.10774draft heads

Introduces Adds several small decoding heads on the target's last hidden state, head k predicting the token k+1 steps ahead; top candidates from each head form a tree verified in one pass with tree attention. No separate drafter model.

Falls short Each head guesses its position blind to the tokens drafted before it, so later heads are often wrong; the tree shape is fixed offline, and the heads are bolted onto a model pretrained only for next-token prediction.

Answered by Hydra, EAGLE, ReDrafter, EAGLE-2, MTP

Jan 2024

EAGLE

ICML '24arXiv 2401.15077feature-level drafting

Introduces A one-layer drafter autoregresses on the target's final hidden states, taking the current feature plus the next sampled token (which resolves sampling uncertainty), and decodes tokens through the target's LM head; candidates form a static tree.

Falls short The tree has a fixed shape regardless of context, spending budget on unlikely branches, and drafting is still one sequential pass per depth, so draft latency grows with draft length.

Answered by EAGLE-2, ParallelSpec

Feb 2024

Hydra

COLM '24arXiv 2402.05109draft heads

Introduces Replaces Medusa's independent heads with sequentially dependent ones: each head also sees the tokens drafted before it, which raises draft accuracy. Hydra++ adds distillation from the target and architecture tweaks.

Falls short Each draft depth still needs its own head, and the candidate tree is a fixed shape tuned offline, so draft length and branching cannot adapt to how predictable the context is.

Feb 2024

Lookahead

ICML '24arXiv 2402.02057Jacobi decoding

Introduces Runs Jacobi-style parallel guessing of several future positions inside each forward pass, collects the n-grams this produces into a pool, and verifies pool entries that start with the current token in the same pass. No drafter or datastore.

Falls short Each step spends many extra FLOPs on the lookahead branch, so it pays off only when compute sits idle, as at small batch; drafts need an exact n-gram match in the pool, which often fails.

Answered by LogitSpec

Feb 2024

Sequoia

NeurIPS '24arXiv 2402.12374token trees

Introduces Chooses the draft tree shape by dynamic programming to maximize expected accepted tokens for a given budget, picks tree size and depth per hardware, and verifies with sampling without replacement so it holds up across temperatures.

Falls short Tree sizes are tuned for GPU-resident targets, where verification cost grows with tree size. For offloaded targets, a pass over thousands of tokens costs about the same as one, so far larger trees would pay off.

Answered by SpecExec

Mar 2024

ReDrafter

arXiv '24arXiv 2403.09919draft heads

Introduces A small RNN draft head conditioned on the target's hidden states drafts with beam search; dynamic tree attention merges prefixes shared across beams before verification, and the head is trained by distillation from the target.

Falls short Drafting is still one sequential RNN step per depth, and beam width and length are fixed settings, so draft cost does not adapt to the context; the head must be retrained for each target.

Mar 2024

Block verif.

ICLR '25arXiv 2403.10444verification rule

Introduces Verifies the draft as a block: whether to accept a prefix is decided with probabilities computed over the whole block. Provably optimal for a single draft, never worse than token-by-token verification, and still exactly lossless.

Falls short It covers a single draft chain only, with no trees or multiple drafts, and drafters trained with token-level losses are not tuned to its rule; the measured gain is modest, about 5 to 8% wall-clock.

Answered by BV loss, Traversal verif., HSD

Apr 2024

LayerSkip

ACL '24arXiv 2404.16710self-speculation

Introduces Trains the model with layer dropout (higher for later layers) and an early-exit loss through a shared LM head, so early layers become usable predictors; at inference it drafts by exiting early and verifies with the remaining layers, reusing their activations and cache.

Falls short The model itself must be pretrained or fine-tuned with this recipe, which changes the weights being served; off-the-shelf checkpoints give poor early exits and cannot use it as is.

Apr 2024

Kangaroo

NeurIPS '24arXiv 2404.18911self-speculation

Introduces Self-speculation from a fixed shallow exit: the target's first few layers plus a small trained adapter form the drafter, and drafting halts as soon as the draft's confidence in the next token falls below a threshold.

Falls short Each draft token still runs a block of the target's own layers, so drafting is not cheap, and the exit depth is fixed for all inputs; with single-chain verification the reported speedup tops out near 1.7x.

Apr 2024

MTP

ICML '24 · DSv3arXiv 2404.19737multi-token prediction

Introduces Pretrains the model with extra output heads that predict several future tokens from a shared trunk; besides better sample efficiency, the heads serve as a built-in drafter for self-speculative decoding. DeepSeek-V3 uses a sequential variant.

Falls short The heads must be trained in from pretraining, so existing checkpoints cannot adopt it cheaply; the paper also finds the gains mainly for larger models and code, with small models sometimes hurt.

Apr 2024

TriForce

COLM '24arXiv 2404.11912long context

Introduces For long contexts, a three-level hierarchy: the target itself, attending to a retrieved sparse subset of its KV cache, drafts for the full model, and a tiny model with a short sliding cache drafts for that sparse drafter.

Falls short Designed for batch 1. Its middle drafter runs the full target weights, so drafting stays heavy, and the extra sparse cache costs memory while giving only moderate acceptance.

Answered by MagicDec, QuantSpec, LongSpec, SpecExtend

May 2024

SpecDec++

COLM '25arXiv 2405.19715draft length

Introduces Sets draft length on the fly: a trained head on the drafter predicts each draft token's acceptance chance, and drafting stops once the predicted chance that some token gets rejected passes a threshold, the form the paper proves optimal.

Falls short The acceptance head must be trained for each drafter and target pair, the method handles a single chain only, and it was evaluated on one Llama-2-chat model pair.

May 2024

DSI

ICLR '25arXiv 2405.14105async / multi-device

Introduces Speculation parallelism: drafters keep running ahead while several target instances on separate GPUs verify earlier drafts concurrently, so no one waits for a verification to finish; provably no slower than SD or plain decoding, with any drafter.

Falls short It trades hardware for latency: overlapping verifications need several target instances across GPUs, and the paper's speedups are measured in simulation.

Jun 2024

EAGLE-2

EMNLP '24arXiv 2406.16858dynamic trees

Introduces Makes EAGLE's draft tree dynamic: the drafter's own confidence stands in for acceptance probability, so the tree grows its most promising branches and keeps only the top-scoring candidates for verification, adapting shape to each context.

Falls short The drafter is trained on the target's true features but at inference feeds on its own predictions, so errors compound with depth (exposure bias); its feature-regression loss also limits what more training data can buy.

Answered by EAGLE-3, HASS, GRIFFIN

Jun 2024

SpecExec

NeurIPS '24arXiv 2406.02532token trees

Introduces For targets offloaded to CPU RAM on consumer GPUs, where one pass over thousands of tokens costs about the same as one: builds a huge draft tree from the drafter's most probable continuations and verifies it in a single target pass.

Falls short The gain depends on verification being nearly free in tree size, which holds only when weight transfer dominates, as with offloading; on GPU-resident targets such large trees waste compute.

Jun 2024

SmartSpec

arXiv '24arXiv 2406.14066serving under load

Introduces Controls speculation in a serving system (vLLM): estimates goodput, accepted tokens per unit time, from predicted acceptance and a batch latency model, and each step sets the draft length, down to zero, that maximizes it.

Falls short At large batch it mostly switches speculation off, because verification turns compute-bound and extra tokens cost real time, so the speedup still vanishes under load; it also optimizes throughput with no notion of latency SLOs.

Answered by MagicDec, AdaSpec

Aug 2024

HASS

ICLR '25arXiv 2408.15766drafter training

Introduces Trains an EAGLE-style drafter under inference-like conditions: harmonized context alignment feeds it its own features from earlier draft steps during training, and harmonized objective distillation focuses the loss on the target's top-ranked tokens.

Falls short Training still includes positions where the drafter's inputs have drifted far from the target's, and these badly misaligned tokens distort optimization, so part of the train/inference gap remains.

Answered by GRIFFIN

Aug 2024

SpecDiff

NAACL '25arXiv 2408.05636parallel draftingour path

Introduces Uses a discrete diffusion language model as the drafter: it produces the whole draft block in a few parallel denoising steps, so drafting cost no longer grows with draft length, and standard verification keeps the output exact.

Falls short The diffusion drafter is a large standalone model blind to the target's internal state, and it drafts positions largely independently, so acceptance decays along the block; its token-level training ignores accepted length.

Answered by DFlash, DiffuSpec, SpecDiff-2

Aug 2024

PEARL

ICLR '25arXiv 2408.11850async drafting

Introduces Overlaps drafting and verification: pre-verify checks the first draft token while the rest are still being drafted, and post-verify keeps drafting while the target verifies, which also makes the draft length adaptive.

Falls short Post-verify drafts assume the current draft is accepted; after a rejection they are discarded and drafting restarts from the corrected token while the target waits, so drafting is back on the critical path.

Answered by SSD

Aug 2024

MagicDec

ICLR '25arXiv 2408.11049serving under load

Introduces Shows that for moderate to long contexts SD speeds up even large batches, because KV-cache reads, which grow with batch and length, dominate; drafts with a sparse, StreamingLLM-style KV cache whose cost stays flat, chosen by a performance model.

Falls short The self-drafter still runs the full target weights over a fixed sparse window, so drafting stays heavy, the extra cache costs memory, and acceptance drops when needed context falls outside the window, as in long reasoning traces.

Answered by Cassandra, QuantSpec, SparseSpec, LongSpec, SpecExtend

Oct 2024

SWIFT

ICLR '25arXiv 2410.06916self-speculation

Introduces Plug-and-play self-speculation that chooses which of the target's layers to skip on the fly, searching for a good skip set from the current input during decoding, with no training and no offline search.

Falls short Layer skipping is coarse: a draft pass still reads the weights of every kept layer, which dominates cost at batch 1, and a model with layers removed drafts poorly, so speedups stay around 1.3 to 1.6x.

Answered by Cassandra

Oct 2024

ParallelSpec

arXiv '24arXiv 2410.05589parallel drafting

Introduces Trains a drafter that predicts k future tokens in one forward pass by appending k mask tokens, replacing autoregressive drafting inside frameworks such as Medusa and EAGLE, so draft cost no longer grows with draft length.

Falls short The parallel drafter is aligned to a single target and must be retrained for every new target model, which multiplies training cost across model families.

Answered by PARD

Oct 2024

Multi-draft opt.

ICLR '25arXiv 2410.18234multi-draft

Introduces Analyses the optimal token-level rule for choosing among several independent drafts: it decomposes into importance sampling that picks one candidate token, followed by ordinary single-draft speculative sampling, and derives practical weighted importance-sampling schemes from this.

Falls short Closed-form optimal acceptance is derived only for two identical drafters; beyond that the proposed schemes are approximations, and the analysis covers token-level selection only, leaving open how multi-step draft trees should branch.

Oct 2024

AMUSD

ISCAS '25arXiv 2410.17375async / multi-device

Introduces Runs the draft and target models asynchronously on separate GPUs: the drafter keeps generating while the target verifies, and on a rejection both roll back to the last verified token.

Falls short After each rejection, everything drafted past the error is discarded and drafting restarts on the critical path; it also needs a second device for the drafter.

Answered by SSD

Nov 2024

SuffixDecoding

NeurIPS '25arXiv 2411.04975retrieval draftingour path

Introduces Model-free drafting from suffix trees over the prompt and past outputs, with draft length set by how long the matched pattern is; a hybrid mode falls back to EAGLE-3 when the suffix match scores poorly. Strong on repetitive agentic workloads.

Falls short It relies on repetition, so on open-ended, high-entropy text matches are rare and gains fade. In RL rollouts and multi-sample generation, samples of one prompt share content, yet each is drafted alone; results are mostly at batch 1.

Answered by DAS, RhymeRL, Multi-sample SD, STAND, Seer, SRT

Nov 2024

SAM Decoding

ACL '25arXiv 2411.10666retrieval drafting

Introduces Finds the longest exact suffix match with a suffix automaton built over both a static text corpus and the current prompt plus output, at amortized O(1) cost per step; when the match is short it hands off to another drafter such as EAGLE-2.

Falls short Drafts still need exact suffix matches, so on text with little repetition it falls back to the auxiliary drafter, and its gain on top of EAGLE-2 is small (about 3 to 11%); the static corpus stays domain-bound.

Jan 2025

Hetero-vocab SD

ICML '25arXiv 2502.05202cross-vocab drafting

Introduces Lets any off-the-shelf model draft for a target with a different tokenizer. Drafts are decoded to text and re-tokenized for exact-match checks (SLEM), verified by string-level rejection sampling (SLRS), or restricted to shared tokens (TLI), all lossless without retraining.

Falls short Mismatched token boundaries cost acceptance: exact matching accepts less than rejection sampling at T>0, string-level rejection sampling gets expensive fast for vocabularies with long tokens, and TLI loses all draft mass outside the vocabulary overlap.

Jan 2025

AdaServe

EuroSys 2026arXiv 2501.12162serving under load

Introduces Serves requests with different per-token latency SLOs by splitting a hardware-profiled token budget each iteration: every request first gets the most probable draft-tree nodes it needs to meet its SLO, and the leftover budget goes to the globally most promising nodes.

Falls short The verification budget is fixed per iteration, so each request's share shrinks as load rises and per-request acceptance falls with RPS. Evaluated only with small same-family drafters on FlexFlow Serve.

Feb 2025

GRIFFIN

NeurIPS '25arXiv 2502.11018drafter training

Introduces Trains an EAGLE-style drafter with multi-step unrolling but masks the loss on positions decoding would never reach, where an earlier ground-truth token falls outside the drafter's top-k, and feeds token embeddings back in to correct drift in its self-generated features.

Falls short Still drafts one token per serial pass, and its multi-pass training costs more than EAGLE's. The fix stays inside the EAGLE-2/HASS feature-drafter design, and the gain is modest (about 8% longer acceptance).

Feb 2025

QuantSpec

ICML '25arXiv 2502.10424long-context self-speculation

Introduces Self-speculation for long contexts: the draft is the target itself with 4-bit weights and a 4-bit KV cache. The cache is stored as upper and lower 4-bit halves, so the draft reads one half and the target rebuilds INT8 from both, with no second cache.

Falls short Lossless only relative to a target that itself runs on an INT8 KV cache, not the FP16 model. The draft is still the full-depth model, so each draft token costs a full 4-bit pass, and gains need KV loading to dominate.

Feb 2025

LongSpec

ACL '26arXiv 2502.17421long context

Introduces A one-block drafter for long contexts with constant memory: sliding-window self-attention for local text plus cache-free cross-attention to the target's KV cache. Anchor-offset position indices let short-context training generalize to long inputs, and Hybrid Tree Attention keeps verification on fast prefix kernels.

Falls short Needs a trained drafter per target. Its cross-attention sees only target KV committed at the last verification, so later draft positions condition on stale context, and drafting remains one serial pass per token.

Feb 2025

Medusa dynamic tree attention

arXivarXiv 2502.05947token trees

Introduces Replaces Medusa's fixed candidate tree with one rebuilt every step: a priority queue picks the top candidates under the product of the heads' top-m marginals, which yields a prefix-closed tree that follows the heads' current confidence.

Falls short Scoring by a product of per-head marginals treats positions as independent, so joint continuations are misjudged. The unoptimized version ran about 10% slower than Medusa in wall-clock, and it was tested only on Vicuna-7B with MT-Bench.

Mar 2025

EAGLE-3

NeurIPS '25arXiv 2503.01840draft heads

Introduces Drops EAGLE's feature regression: the drafter predicts tokens directly from fused low, mid and high-layer target features, and 'training-time test' trains it on its own multi-step outputs. Without the feature loss, acceptance keeps rising as drafter training data grows.

Falls short Drafting is still autoregressive, one serial pass per draft token, and token-level training does not directly maximize accepted length. Acceptance collapses past the trained draft horizon, and speedups shrink at large batch (about 1.01x in vLLM at batch 56).

Answered by P-EAGLE, DART, DFlash, LK losses, GTO, VAT, KVShot, Attention Drift, ECHO, ReSpec, TLT

Mar 2025

Multi-sample SD

EMNLP Findings '25arXiv 2503.05330sibling drafting

Introduces For self-consistency and Best-of-N, drafts come from the other parallel samples of the same prompt: fuzzy suffix matches across paths fill a draft pool, merged into a weighted DAG whose highest-consensus path is proposed. No draft model or datastore is needed.

Falls short Reports acceptance but no batched wall-clock speedup, since it was never combined with batch-oriented SD. DAG aggregation grows costly with many paths, acceptance drops at high temperature as paths diverge, and only GSM8K and MATH were tested.

Mar 2025

AdaSpec

SoCC '25arXiv 2503.05096serving under load

Introduces Adapts speculation to live load and SLOs: the drafter stops once draft confidence predicts falling efficiency, and the verifier spends each batch's verification budget on the drafts most likely to be accepted, which gives per-request lengths under a TPOT constraint.

Falls short Its decisions hinge on draft-model confidence as a proxy for acceptance and on a latency model whose coefficients are fitted per platform, parallelism and model pair. Evaluated only with small separate chain drafters (68M to 1B).

Apr 2025

PARD

ICLR '26arXiv 2504.18583parallel drafting

Introduces Turns a small standalone LM into a target-independent parallel drafter: appended mask tokens let it predict K future tokens in one pass, so one drafter serves a whole model family. Conditional drop-token training keeps fewer positions at deeper depths, cutting adaptation cost about 3x.

Falls short It reads no target hidden states and its masked positions ignore each other, so acceptance decays at deeper positions. CE training does not target accepted length, and speedup falls steeply with batch (3.63x at batch 1, 1.33x at 16).

Answered by DFlash, PARD-2

May 2025

Traversal verif.

NeurIPS '25arXiv 2505.12398verification rule

Introduces Verifies a sampled draft tree leaf-to-root, judging each whole path by its sequence-level probability and falling back to siblings or the parent only after rejection. It keeps candidates that root-first token checks discard, stays lossless, and is optimal for a single chain.

Falls short No gain at greedy decoding, where lossless verifiers coincide, and visiting every node adds verification overhead. Losslessness requires children sampled from the drafter, which excludes deterministic top-k trees, and measured acceptance gains are a few percent.

May 2025

SpecExtend

ACL Findings '26arXiv 2505.20776long context

Introduces A training-free add-on for long inputs: FlashAttention and Hybrid Tree Attention speed prefill and verification, and Cross-model Retrieval uses the target's attention scores to choose which context chunks the small drafter keeps in its KV cache, improving draft speed and accuracy.

Falls short The target still attends over its full KV cache at every verification, so per-token speed keeps falling as inputs grow. By its authors' account it stays below drafters trained for long inputs such as LongSpec.

May 2025

MoESD

NeurIPS 2025 (spotlight per arXiv comment)arXiv 2505.19645MoE cost model

Introduces Shows SD can pay off for MoE targets at moderate batch: once the batch already activates every expert, verifying extra draft tokens adds little expert-weight traffic, so speedup rises then falls with batch. Introduces 'target efficiency' and a fitted roofline model to predict it.

Falls short Assumes KV-cache traffic is small next to parameter traffic, so long-context, KV-dominated regimes are out of scope. Validated only with up to 4 draft tokens, batches up to about 100 and 4 GPUs, without large expert-parallel deployments.

May 2025

Scylla (Scaling Laws for SD)

arXivarXiv 2505.07858drafter scaling

Introduces Fits scaling laws for drafters: acceptance grows log-linearly with drafter pretraining tokens and drafter depth, and the best tree top-k depends on batch size. Applies them in Scylla, an EAGLE-style drafter pretrained on 10B tokens with extra decoder layers.

Falls short The laws come from dense Transformers only, and pretraining gains saturate beyond roughly 50B tokens. Deeper drafters add draft compute, acceptance versus batch size was not measured, and the code was not released.

May 2025

STree

NeurIPS 2025arXiv 2505.14969hybrid models

Introduces Brings tree verification to Mamba-2 and hybrid models: state-transition decays are accumulated along a tree mask, so a packed token tree is verified in one tree-scan pass without recomputing shared prefixes, and activation replay rebuilds the state of the accepted path.

Falls short The tree scan adds overhead that makes it slower at short inputs, and it was shown only up to 8B (MambaInLlama-8B with a distilled 2-layer SSM drafter) with static trees.

Jun 2025

STAND

EMNLP '25arXiv 2506.04708model-free n-grams

Introduces A model-free drafter for test-time scaling: an n-gram table over the reasoning traces generated so far keeps per-context token probabilities, so drafts are sampled stochastically with Gumbel-Top-K into a static tree tuned on data. It exploits how often reasoning paths repeat patterns.

Falls short As an n-gram lookup it can only propose continuations already seen in the traces. Gains shrink in batch decoding (30% latency cut versus 58% single-trajectory), and all timings use HuggingFace with a Python n-gram module, not vLLM or SGLang.

Jun 2025

SwiftSpec

ASPLOS 2026arXiv 2506.11309async / multi-device

Introduces Takes drafting off the critical path: draft and target run concurrently on separate tensor-parallel GPU groups. The draft keeps growing a likely token tree, re-rooted after each verification with KV reuse, while the target verifies an 8-token subtree; fused kernels cut small-batch TP latency.

Falls short Hard to combine with EAGLE-style drafters, which need target features that a drafter running ahead does not have yet. Its int4 latency kernels do not suit high-throughput serving, and results cover single requests with 4-bit AWQ targets.

Jul 2025

LogitSpec

ACL Findings '26arXiv 2507.01449retrieval drafting

Introduces Uses the last logit twice: besides the next token, its top-ranked entries often contain the token after it. Those candidates join the next token in a two-token query against prompt n-grams, which finds correct references more often than single-suffix retrieval. Training-free.

Falls short It retrieves only from the prompt, so short prompts give little to copy, and by its own account its end-to-end speedup trails draft-model methods. Main results are greedy at batch size 1.

Aug 2025

RhymeRL

arXiv '25arXiv 2508.18588RL rollouts

Introduces Speeds RL rollouts by drafting from the same prompt's responses in earlier epochs (HistoSpec): suffix trees over past rollouts, built asynchronously, supply drafts, and an AIMD rule sets draft length. HistoPipe also uses past lengths to balance rollout workers.

Falls short Drafts are verbatim copies of history, so they need the prompt to recur across epochs and help only where the policy still repeats itself. Sibling responses being generated in the same step contribute nothing.

Sep 2025
