## A. Parallel / block / diffusion drafters

### PARD — PARD: Accelerating LLM Inference with Low-Cost PARallel Draft Model Adaptation
*arXiv 2504.18583 · 2025-04 · ICLR 2026* · builds on: vanilla SD, Mask-Predict, ParallelSpec, PaSS

- **Problem:** Target-specific draft heads are costly to train; AR small drafters are slow.
- **Contribution:** Adapts a small standalone AR LM into a target-independent parallel drafter that predicts K future tokens in one pass using a shared mask token (extrapolates to K_infer > K_train). Conditional Drop-token (COD) training keeps geometrically fewer positions at deeper prediction depths while preserving prefix KV integrity, cutting adaptation cost ~3x.
- **Limitation:** Scope (experiments): speedup falls steeply with batch (3.63x at bs=1 to 1.33x at bs=16 on Llama3.1-8B) and throughput peaks at K_infer=12, dropping at 16. No target features or intra-block dependency, so deep positions decay (PARD-2 Fig. 2a).
- **Evaluated:** draft ≤ 16, batch ≤ 16; acceptance length Not reported in PARD (gives 1-α/4-α = 0.93/0.90 on HumanEval, plus TPS); PARD-2 Table 1 measures PARD at 6.71 (Llama3.1-8B HumanEval, K=16, T=0)
- **Long drafts:** No: positions independent given prefix and masks; COD reduces supervision at deeper positions. · per-position data: Only average acceptance at draft length 1 vs 4 (Table 2: 0.93 vs 0.90 HumanEval); no per-position curve.
- *Note:* ID correct. Venue: repo README news 'PARD is accepted to ICLR'26' (2026-01-26) and DSpark bibliography (ICLR 2026, OpenReview XbOyv7iVGL); arXiv comment still says 'submitted for possible publication'. Drafter is a separate small LM (e.g., Llama-3.2-1B) shared across a model family; K_train=8 default. Temperature not stated.

### DiffuSpec — DiffuSpec: Unlocking Diffusion Language Models for Speculative Decoding
*arXiv 2510.02358 · 2025-09 · Findings of ACL 2026* · builds on: SpecDiff (Christopher et al.), vanilla SD, Dream-7B dLLM

- **Problem:** AR drafters are sequential; dLLM lattices are not left-to-right consistent; preset length.
- **Contribution:** Training-free use of a pretrained 7B dLLM (Dream-7B) as a one-pass drafter. Causal-consistency path search beam-searches an entropy-pruned per-position candidate lattice scored by DLM log-prob plus a 3-gram causal proxy, and an adaptive draft-length controller sets the next block size from EOS-aware generation and acceptance EMAs.
- **Limitation:** Paper-stated future work: DLM drafting lacks KV reuse/fused kernels and the causal proxy is weak. Scope: greedy-only (T=0), batch 1, single A100, one 32B target with a memory-heavy 7B drafter.
- **Evaluated:** draft ≤ 100, batch ≤ 1; acceptance length 6.99 mean accepted tokens (Qwen2.5-32B target, Dream-7B drafter, Spec-Bench, greedy, Table 1); 7.33 with 10 refinement steps (slower)
- **Long drafts:** Yes, indirectly: n-gram-guided lattice path search pushes first mismatch rightward; ADL avoids oversized blocks. · per-position data: No per-position curve; MAT vs fixed draft length plateaus (6.49 at k=30, 6.69 at k=100).
- *Note:* ID correct; v1 dated 2025-09-28 although id is 2510. Acceptance ratio uses an L2R masked proxy q while the token is chosen by beam search; only T=0 evaluated, so losslessness under sampling is not demonstrated. ADL operates in k∈[20,30].

### SpecDiff-2 — SpecDiff-2: Scaling Diffusion Drafter Alignment For Faster Speculative Decoding
*arXiv 2511.00606 · 2025-11 · MLSys 2026* · builds on: SpecDiff, DistillSpec, EAGLE-2

- **Problem:** Diffusion drafter marginals misaligned with AR verifier, worst at later window positions.
- **Contribution:** Streak-distillation fine-tunes a 7B discrete-diffusion drafter to maximize a pathwise surrogate of expected accepted streak (sum over m of products of drafter marginals on verifier-sampled paths). Self-selection samples K drafts from one pass's marginals, scores all with verifier conditionals in one tree-attention pass, and verifies the best with point-mass acceptance (accept w.p. p(x), residual excludes x).
- **Limitation:** Paper-stated: formal analysis of the greedy-acceptance rule and the optimal diffusion-drafter size remain open, and kernels/KV caching for diffusion drafts are lacking. Scope: 7B drafters too slow for 13-14B verifiers; batch size never reported.
- **Evaluated:** draft ≤ 128, batch ≤ —; acceptance length 7.71 tokens/draft incl. bonus (Qwen2.5-72B, HumanEval, T=1, DiffuCoder-7B drafter, γ=32, Table 2)
- **Long drafts:** Yes: streak objective weights later window positions by survival; 3.2x higher later-position acceptance than AR-style distillation. · per-position data: Yes (Fig. 2, γ=32): α_j decays steeply then plateaus (~0.16 streak-distill vs ~0.06 AR-distill, ~0.03 base).
- *Note:* ID correct. Main γ=32 (DiffuCoder) / 16 (DiffuLLaMA); γ ablation 8-128 (unaligned SpecDiff) peaks at 32. Point-mass acceptance after verifier-based selection is still lossless (selection uses distributions, not verifier coin flips). Batch size unknown (2xA100 for 70B+).

### DART — DART: Diffusion-Inspired Speculative Decoding for Fast LLM Inference
*arXiv 2601.19278 · 2026-01 · arXiv* · builds on: EAGLE-3, Medusa, Lookahead / N-gram

- **Problem:** EAGLE-3 multi-step AR rollout makes drafting the latency bottleneck.
- **Contribution:** Single-layer drafter on fused target hidden states appends d-1 mask tokens and emits d shifted next-token logits in one pass (causal mask within the block), trained with prefix-shared masks and annealed KL (γ=0.6). Builds the draft tree by beam search over per-position top-k combining draft log-prob with an N-gram continuity score.
- **Limitation:** Scope (no limitations section): designed for a short horizon (d=8) with early-position emphasis, and τ (~3.6-4.1) does not beat EAGLE-3's; speedup decays to 1.45x at batch 64.
- **Evaluated:** draft ≤ 8, batch ≤ 64; acceptance length 4.08 mean (LLaMA2-Chat-7B, T=0, d=8 tree, Table 1); up to 4.59 on CodeAlpaca (N-gram ablation, Table 2)
- **Long drafts:** No: KL annealing favors early positions; only N-gram continuity scoring couples adjacent tokens during tree pruning. · per-position data: Yes (Table 4): unconditional top-1 accuracy per future position decays steeply, 75.5%→44.7%→29%→19%→13.8%→11.2%.
- *Note:* ID correct. ICML-style template but no acceptance evidence found. Per-position numbers are marginal accuracy vs ground truth, not conditional acceptance. Domino measures public DART checkpoints (60-node tree) at τ≈2.6-3.0 on Qwen3.

### DFlash — DFlash: Block Diffusion for Flash Speculative Decoding
*arXiv 2602.06036 · 2026-02 · ICML 2026* · builds on: EAGLE-3, Block diffusion LMs (BD3-LM), PARD

- **Problem:** Autoregressive drafting cost grows with draft length, capping drafter depth and speedup.
- **Contribution:** Lightweight 5-layer block-diffusion drafter that fills a 16-token masked block in one forward pass, conditioned on fused multi-layer target hidden states injected as extra K/V into every draft layer. Trained on target-generated responses with randomly anchored blocks and exponentially decaying per-position loss weights; shares the frozen target embedding/LM head.
- **Limitation:** Scope (experiments): speedup shrinks with concurrency (Qwen3-4B Math500 4.8x at c=1 to 2.9x at c=32) and the paper notes large blocks raise verification cost when compute-bound, leaving adaptive block-size scheduling to future work. Base drafter degrades beyond its 4K training context without long-context fine-tuning.
- **Evaluated:** draft ≤ 16, batch ≤ 32; acceptance length 9.1 (Qwen3.5-27B, HumanEval, block 16, SGLang c=8, App. Table 11); 7.87 on Qwen3-8B MATH-500, T=0 (Table 1)
- **Long drafts:** No: positions predicted independently; loss decay w_k=exp(-(k-1)/γ) deliberately emphasizes early positions. · per-position data: No per-position curve; only notes block-8 drafter fully accepts 35.7% of blocks (Math500).
- *Note:* ID correct. Inco AI's DFlash 2 blog says the same team released DFlash in Jan 2026. DSpark and DFlash 2 measurements show DFlash's conditional acceptance drops sharply after position 1 then plateaus around 0.78-0.83.

### P-EAGLE — P-EAGLE: Parallel-Drafting EAGLE with Scalable Training
*arXiv 2602.01469 · 2026-02 · arXiv* · builds on: EAGLE-3, ParallelSpec, PARD

- **Problem:** EAGLE needs K sequential passes; parallel-drafter training is infeasible at long contexts.
- **Contribution:** Turns EAGLE into a one-pass multi-token drafter: positions after the first use a learnable shared hidden state plus a learned mask-token embedding (unfrozen embeddings, 4 layers). Makes long-context (up to 20K) parallel-prediction training feasible via precomputed sliceable attention masks and within-sequence partitioning for gradient accumulation under COD.
- **Limitation:** Scope (experiments): gains over EAGLE-3 are modest (1.0-1.36x) and shrink at concurrency 4 for large/MoE targets as verification dominates; evaluated only up to C=4, K≤7, chain drafting on one H200. No intra-block dependency modeling; acceptance only matches AR EAGLE-3.
- **Evaluated:** draft ≤ 7, batch ≤ 4; acceptance length 4.5 (Qwen3-Coder-30B, HumanEval, K=5, Table 9)
- **Long drafts:** No: all later positions share one learned hidden state; position-specific encodings hurt by 7-15%.
- *Note:* ID correct. Trained with K_train=8, inference K≤7 (training at 8 beats 5 by ~4%). Sampling temperature not stated. Only aggregate MTP-position accuracy (57.9%) reported, no per-position acceptance.

### PARD-2 — PARD-2: Target-Aligned Parallel Draft Model for Dual-Mode Speculative Decoding
*arXiv 2605.08632 · 2026-05 · arXiv* · builds on: PARD, EAGLE-3, DFlash

- **Problem:** Uniform or fixed-decay position losses misalign training with consecutive-acceptance objective.
- **Contribution:** Confidence-Adaptive Token (CAT) loss weights each future-token CE+KD term by the cumulative product of target confidences along the ground-truth prefix, a proxy for the probability that position is reached in verification. Stochastic gating of fused target hidden features lets one standalone PARD-style drafter run in target-dependent or target-independent mode.
- **Limitation:** Scope (experiments): all acceptance results are greedy (T=0) chain decoding with tree disabled, on Llama3.1-8B/Qwen3 ≤32B with A100s; no limitations section. The deep-position comparison vs PARD confounds CAT with a longer training horizon (K=16 vs PARD's 8).
- **Evaluated:** draft ≤ 16, batch ≤ 64; acceptance length 9.19 (Llama3.1-8B, HumanEval, K=16, T=0, target-dependent mode, Table 1)
- **Long drafts:** Yes, indirectly: CAT weights loss by estimated prefix survival; per-position acceptance stays ~0.91-0.94 to position 16. · per-position data: Yes (Fig. 2a, HumanEval, Llama3.1-8B): PARD decays 0.92→0.47 by pos 16; PARD-2 stays flat ~0.91-0.94.
- *Note:* ID correct. Fig. 2a cumulative τ: PARD saturates ~6.6 by pos 12, PARD-2 keeps rising to ~9.2 at pos 16. PARD's official drafter was trained at K=8, so its collapse after pos ~9 is partly extrapolation. vLLM batch sweep 1-64 (Fig. 1): PARD-2 above PARD and EAGLE-3 at every batch size (~3.9k vs 2.8k TPS/GPU AR at bs=64).

### Domino — Domino: Decoupling Causal Modeling from Autoregressive Drafting in Speculative Decoding
*arXiv 2605.29707 · 2026-05 · arXiv* · builds on: DFlash, Hydra, EAGLE-3

- **Problem:** Parallel drafters lose intra-block causal dependencies; AR drafters pay sequential cost.
- **Contribution:** Adds to a DFlash backbone a 'Domino head': a GRU (d=1024) over embeddings of previously sampled draft tokens plus a low-rank (r=256) logit-space residual correction, run as a fused cheap sequential loop. Trained teacher-forced with a base-anchored curriculum that anneals loss weight from backbone logits to corrected logits to prevent backbone collapse.
- **Limitation:** Paper-stated: targets inference rather than training cost, implementation mainly adapted to SGLang, and speedup varies across hardware. Scope: Qwen3-4B/8B only, concurrency ≤32, and headline tables compare against public DFlash checkpoints trained on different data.
- **Evaluated:** draft ≤ 16, batch ≤ 32; acceptance length 10.12 (Qwen3-4B, GSM8K, block 16, T=0, Transformers backend, Table 1)
- **Long drafts:** Yes: GRU state over sampled predecessors corrects every later position's logits; no per-position evidence shown.
- *Note:* ID correct. Same-data (ShareGPT) ablation: EAGLE-3 τ 5.01 > Domino 4.65 > DFlash 3.90 on GSM8K, yet Domino is fastest. Head on/off ablation: τ 3.49→4.19 (+20%). At c=32 speedups compress to 1.9-2.1x (EAGLE-3 60-node tree 0.4x).

### TreeFlash — TreeFlash: Parallel AR-Approximation for Faster Speculative Decoding
*arXiv 2606.03819 · 2026-06 · arXiv* · builds on: DFlash, DDTree, OPT-Tree

- **Problem:** One-shot drafters' marginals diverge from AR distribution with depth, worse in trees.
- **Contribution:** Adds a SwiGLU 'AR-approximator' that updates each DFlash position's hidden state with the embedding of the preceding token, giving bigram-conditioned per-node distributions. Keeps O(1) drafting via two stages: build a top-M-ary tree from DFlash marginals, evaluate the approximator on its M·γ unique (token, position) pairs in parallel, then select an OPT-Tree; trained with forward KL from a DFlash initialization.
- **Limitation:** Paper-stated: all experiments single-batch with SDPA (large dynamic trees may conflict with multi-batch serving), initialized from DFlash, teacher-forced exposure bias, Qwen-only. Non-leaf tree nodes must lie inside the top-M tree.
- **Evaluated:** draft ≤ 16, batch ≤ 1; acceptance length 11.02 (Qwen3-8B, MATH-500, T=0, tree budget 64, Table 1); mean 9.71 at budget 512 (Qwen3-4B greedy, Fig. 5)
- **Long drafts:** Yes: previous-token conditioning cuts depth-15 TVD to verifier from 0.81 to 0.62; gain over DDTree grows with budget. · per-position data: Yes (Figs. 3-4): TVD vs depth rises steadily (DFlash 0.19→0.81); top-K coverage decays; TreeFlash slower.
- *Note:* ID correct. Verification is an equality check against the target's (sampled) token, lossless at T=1. Most gain over DFlash comes from chain→tree (DDTree ≈63% of τ gain); AR-approx adds +7.5% τ (B=16) to +12.4% (B=64). Beyond depth 9 even the true marginal has higher TVD than TreeFlash. Tree budgets up to 512 nodes.

- **Contribution:** Models request latency as C1/(1-RPS*C2), with batch inferred via Little's Law. - **Long drafts:** no; analysis shows the k that is optimal at batch 1 is too long under load. · per-position data: No; assumes constant per-token acceptance (geometric), synthetically enforced at 50-100%.
- *Note:* ID correct. Analysis paper, and its experiments are not lossless: acceptance is forced by overriding vLLM's rejection sampler, so acceptance cannot vary with load by construction. ### D-cut — D-cut: Adaptive Verification Depth Pruning for Batched Speculative Decoding
*arXiv 2607.14647 · 2026-07 · arXiv* · builds on: DFlash, SpecDec++, ECHO, DSpark

- **Problem:** Fixed-depth long block drafts waste compute-bound batched verification on rejected suffixes
- **Contribution:** Scores every draft position in the batch by its prefix-product drafter confidence (estimated survival probability) and verifies only a global top-K, so each request keeps a contiguous high-confidence prefix and low-confidence suffixes are pruned across requests. K is picked from {25,50,75,100}% of B(D+1) by maximizing estimated accepted tokens divided by a startup-profiled step-latency table C(B,rho).
- **Limitation:** Stated: per-step variable verify shape does not fit CPU-GPU overlap (Spec-V2) or full CUDA-graph capture, so it runs with piecewise graphs only. Scope: built on DFlash only, greedy draft proposals, concurrency <=64, H20/H800.
- **Evaluated:** draft ≤ 15, batch ≤ 64; acceptance length 7.04 (D-cut-16, Qwen3.5-27B, HumanEval, conc. 32, greedy); unpruned DFlash-16 up to 7.87 (Qwen3-4B, Math500)
- **Long drafts:** no; it prunes low-survival deep positions under load rather than raising their acceptance. · per-position data: No depth curve; prefix-product confidence vs acceptance is monotone (AUROC 0.96-0.97, Fig. 7); per-request MAT varies widely (Fig. 2a).
- *Note:* ID correct. Same Tencent team as AngelSpec, which reuses D-cut. MAT is reported only at conc. 32; there is no MAT-vs-concurrency data (MAT(K) is treated as hardware-independent). At conc. 32 DFlash-16 is below AR on all four dense targets (avg 0.67-0.98x) despite avg tau 4.6-6.4. App. B: confidence pruning that depends on the sampled token breaks losslessness under rejection sampling, so a shifted, non-anticipating score is needed.

### H-Spec — H-Spec: Parallel Speculative Decoding Without a Drafter-Side KV Cache
*arXiv 2609.24197 · 2026-09 · arXiv* · builds on: DFlash, DSpark, P-EAGLE

- **Problem:** Block drafters' separate drafter KV cache grows memory and KV-write cost with concurrency
- **Contribution:** Hybrid Mamba-attention block drafter.
